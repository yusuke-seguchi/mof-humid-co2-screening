## Phase 1: データ基盤と母集団構築（Stage 0）

**1.1 ダウンロード自動化** — 検証済みURLをすべて `download.py` に固定化（Zenodo: CoRE MOF 2024/2025・MOSAEC-DB・WS24、Materials Cloud: BW-DB、Europe PMC: Keskin）。チェックサム・再開可能。スクラッチ領域に取得済みのファイルは `data/raw/` へ移設。

**1.2 ローダと正規化** — DB間で異なるカラム名・単位を共通スキーマに正規化。結合キーは CSD refcode（+ 活性化状態サフィックスの正規化）。重複解決ルール: CoRE 2024を優先、MOSAECで補完。

**1.3 Stage 0ゲート実装**（指標サーベイ §6 の表の通り）
- 金属Tier付与: Tier A (Zr/Hf/Ti/Al/Cr) / B (+Fe/Sc/In/Ga) / C (+ランタノイド)
- ML水安定性 P≥0.5（CoRE 2024ラベル。無い構造はWS24モデルまたは金属ヒューリスティクスで補完し、根拠フラグを保持）
- 熱・活性化安定性 / PLD≥3.3 Å / 構造健全性（ASR・MOSAEC通過）
- OMSフラグ・アミン官能基フラグ（Track 2分離用。ゲートでなくフラグ）
- 化学吸着性サイト持ちは `track2_candidates` テーブルへ分離

**成果物**: `data/processed/pool.parquet`（想定 ~5,000件+Tier/フラグ）、統計サマリ、pytest一式。
**目安工数**: 実装0.5日＋ダウンロード待ち。

## Phase 2: ML粗選別（Stage 1）

**2.1 学習テーブル** — BW-DB 324,426件（CO₂吸着量@0.15bar/298K、混合CO₂/N₂、吸着熱、作業容量2種、CO₂/N₂選択性）。特徴量は転移に強いものを優先（幾何+電荷統計+官能基。金属one-hotは不使用 — RetNeXt 2026の知見）。リーク対策: 構成SBU・トポロジーでグループ化したsplit（Jablonka 2023準拠）。

**2.2 モデル** — LightGBMアンサンブル（seed×5以上）。ターゲット: CO₂吸着量（混合0.15bar）、CO₂/N₂選択性、Q_st。アンサンブル分散を不確実性として全予測に付与。
検証: (a) ホールドアウトR²、(b) 可能ならhMOF（MOFX-DB）へのLODO転移テスト、(c) Keskin 3,816実験refcodeで選択性の順位相関（仮想→実験シフトの定量化）。

**2.3 Stage 1選抜** — 予測吸着量×Henry選択性のParetoバンド上位~20–30%＋**高不確実性構造は落とさず持ち越し**（安全側運用）。Q_st窓30–55 kJ/molはソフト適用。極端な親水クラス（CoRE KH class）のみ除外。

**成果物**: `stage1_ranking.parquet`（~1,000–1,500件）、検証レポート（LODO・校正曲線込み）。
**目安工数**: 1日。

## Phase 3: 物理計算（Stage 2 — Widom + GCMC）

**3.1 環境構築** — conda環境に RASPA2（conda-forge）+ zeopp。CIF: CoRE 2024公開分から取得、PACMAN電荷を適用。CCDC登録完了後にCSD-modified分を追加（増分実行できる設計に）。

**3.2 パイロット** — 代表20構造（セルサイズ・金属Tierを層化サンプリング）で実行時間を実測し、全体計画の係数を補正。**GO/NO-GO判断点**。

**3.3 Widom挿入（全母集団~5,000件）** — CO₂/H₂O Henry係数+Q_st。6並列バックグラウンド、想定2–3日。ML予測との相互検証（大きく食い違う構造は要注意フラグ）。

**3.4 混合GCMC（Paretoバンド上位~300件）** — CO₂:N₂=15:85、0.15/0.85 bar、313 K＋脱着点（0.1 bar）。想定~2日。
**3.5 湿潤チェック（GCMC生存者）** — 三成分GCMC短時間実行またはサイトエネルギー比較で E(CO₂)≥E(H₂O) / 湿潤保持率≥80–90% / CO₂/H₂O比≥1 を判定。

**成果物**: `stage2_results.parquet`、作業容量×混合選択性Pareto、湿潤合格リスト。
**目安工数**: 実装1日＋計算5–6日（放置）。

## Phase 4: 統合ランキングとレポート（Stage 3の一部）

- 統合スコア表: GCMC作業容量×選択性Pareto＋再生性R＋耐水性根拠＋Tier
- **サニティチェック**: CALF-20/SIFSIX-3/Al-PMOF/UiO-66系が妥当な位置に来るか。Mg-MOF-74/HKUST-1は金属ゲートで除外されていることを確認（ゲートの妥当性検証として記録）
- Track 2（化学吸着候補）リストをODAC23突合の定性情報付きで併記
- 最終候補~50件+手法・検証・限界を記したレポート（docs/）
- （オプション、母集団確定後に判断）簡易PVSAによる比エネルギー×生産性Pareto

**目安工数**: 1日。

## 主要な技術的決定（デフォルト案）

| 項目 | 決定 | 理由 |
|---|---|---|
| Python環境 | venv + Python 3.12（ローカル） | 既存環境で確認済み |
| MLフレームワーク | LightGBM（+scikit-learn） | 表形式データの定番、アンサンブル不確実性が容易 |
| GCMCエンジン | RASPA2（conda-forge） | 実績・文献互換。RASPA3移行は必要時 |
| hMOF学習データ | 初期はBW-DBのみ、hMOFはLODO検証用に限定 | MOFX-DB一括取得が重く、BW-DBで条件が揃っているため |
| 閾値管理 | config.py に一元化＋出典コメント | 感度分析・再現性のため |

## リスクと対応

- **CoRE公開分だけでは母集団のCIFが不足** → 記述子ベースのStage 0-1はCIF不要で完走可能。Phase 3はCIFがある構造から順次実行し、CCDC登録後に増分。
- **BW-DB→実験構造のドメインシフト** → Phase 2.2の検証で定量化。校正不能なら Stage 1の選抜を緩め（Paretoバンド拡大）、Widom全数計算の比重を上げる。
- **GCMC時間超過** → パイロット実測で判明次第、クラウドスポット（$30–80）へ切替可能な設計（simulate.pyはジョブディレクトリ独立）。
